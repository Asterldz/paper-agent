# Paper Agent：双 Skill 与受控进化方案

## 实现状态（2026-09-07 更新）

用户已明确要求升级实际应用并使用主流框架。现已采用 **LangGraph.js 1.4.14 + LangChain Core 1.2.9 / OpenAI 1.5.11 + Zod 4.5.4**，不是只添加 Skill 文档。

- 文献助手入口 `hooks/usePaperAssistant.ts` 调用 `literatureGraph.ts` 的实际 StateGraph，包含 plan → tools → plan/answer → verify 的条件循环。
- LangChain `bindTools` 向模型发送真实工具协议，11 个 Zod 校验工具覆盖本地文献、参考原文、外部论文与 Wiki。参考工具先本地再查开放来源；外部来源区分全文、摘要和题录。反馈图也使用 LangGraph。
- 两份 SKILL.md 由 Vite 作为资源加载；个人策略只允许 3 个枚举槽位。明确格式偏好可选择自动采用，模型提出的策略候选需用户审核；支持父版本校验及回滚。
- 助手展示实际工具记录、来源片段、页面跳转、耗时与模型/工具调用次数，并可导出不含正文的运行指标。检查只证明来源位置可定位，不证明模型主张完全被支持。
- 规划最多 4 轮、工具最多 8 次、整次任务 150 秒；规划请求禁用自动重试，答案请求最多一次。引用与工具失败可见，不伪装成功。
- 原有 PDF 划线翻译保留快速通道，LangGraph 在打开助手发起任务时懒加载。顺带修复类型检查暴露的选区文本拼接错误（把字符当作词数组使用），不宣称已全面解决 PDF 分栏。
- 46 项模拟环境机制测试通过；另用真实 Europe PMC 开放论文验证 HTTP 与正文提取链路。未使用用户 API Key 发起真实模型评测，未执行浏览器交互验收。详细验证与边界见项目说明和 LLM Wiki 说明。

**仍未实现：** 任意来源论文全文抓取、系统文件移动、向量语义检索、完整事实支持评估、按答案质量自动晋升策略、后台无人值守进化、跨设备记忆、Token/费用实测及完整任务断点恢复。设备本地状态不是多账号隔离。

以下保留原设计与后续路线，不能把所有路线项当成已实现功能。当前可复现的简历说明见 [项目与验收说明](agent-project.md)。

## 初始设计交付和边界（历史记录）

本轮创建两份应用内 Skill 规范草案及反馈基线，回答“应该如何构建”的设计问题；没有更改线上阅读行为、安装 Agent 运行器、启动后台任务或调用付费模型评测。规范文件不是可执行的权限控制，也不代表已经具备自动进化能力。

- [阅读 Skill](../agent-skills/paper-reading/SKILL.md)：翻译、解释、术语、总结、文献优先问答与参考论文证据追踪。
- [进化 Skill](../agent-skills/paper-reading-evolution/SKILL.md)：把有来源的反馈转换成受限候选改动，并交给独立评测与发布控制器。

它们属于 Paper Agent 项目，不是安装到 Codex 后就能让公开网站生效的插件。采用 SKILL.md 目录格式可以方便以后导入，但宿主仍需实现加载、工具适配、版本管理和权限控制。

## 升级前基线（历史设计记录）

以下描述是升级前的状态，不是当前架构。当前助手已使用 `literatureGraph.ts`、`langchainModel.ts` 和工具循环，见 `agent-project.md`。

当时检查的入口：

- `services/agent/paperAgent.ts`：构造固定任务消息后调用模型。
- `hooks/usePaperAssistant.ts`：预先检索当前文献，按固定逻辑寻找本地参考论文，再调用助手。
- 旧助手单次回答实现：把预备证据和固定系统提示词送给模型，流式输出一次答案；已在开源清理中移除。
- `services/agent/paperRetrieval.ts`：关键词/词频检索、摘要采样和固定阶段说明；不是模型自主选择工具的循环，也不是向量语义检索。
- `types/llm.ts`：目前只有 system/user/assistant 文本消息，没有结构化工具调用/工具结果协议。

因此更准确的现状是“文献检索增强的 AI 阅读应用”。现有界面和缓存可继续利用；不用为了 Agent 名称而重写整个产品。

## 目标架构

保留现有 TypeScript 技术栈，增加应用拥有的 Agent 执行层。是否采用框架与是否构成 Agent 是两回事：核心是模型能根据工具结果决定下一步，而不是把固定按钮流程换个名字。

两条执行路径：

```text
划选翻译 → 校验选区/命中缓存 → 一次流式生成 → 校验完整性 → 兼容缓存

复杂问答 → 加载阅读 Skill + 当前用户偏好
        → 模型选择受限工具 → 执行工具并返回真实证据
        → 证据不足则继续检索（有预算和停止条件）
        → 生成答案 → 核验来源及支持关系 → 展示可追踪结果
```

普通翻译不强制经过多轮规划、参考论文追踪或进化评测，避免 Agent 化反而拖慢最常用的功能。

### 运行器必须补齐的能力

1. 结构化工具注册表、参数校验、调用结果协议与有限状态循环。模型只能选择已注册工具，不能输出任意代码作为执行指令。
2. 任务状态保存 documentId、selectionId、runId、skillVersion、profileVersion、模型配置、预算和证据。每个任务固定版本，切换文献/选区时正确取消。
3. 证据记录保留 documentId、内容版本、PDF 页序号、可用时的印刷页码、片段位置、来源链接和访问状态。显示“已阅读参考论文”必须有实际读取的片段；仅下载文件不算全文已读。
4. 检查引用是否指向真实读取内容，并检查该内容是否支持主张；格式合法或页码存在并不等于结论正确。
5. 显示简短的工具活动、来源和限制，不显示隐藏思考链，也不把预设的阶段文案当成真实执行日志。

### 工具的最小集合（待实现的接口，不是当前已有能力）

| 工具 | 用途 | 边界 |
| --- | --- | --- |
| search_document / read_passage | 在指定文献中检索、读取上下文 | 仅当前任务可访问文献；返回证据 ID 与页位置 |
| resolve_reference | 从引用编号定位题录与本地文献 | 不把相似标题自动当成同一论文，核对 DOI/题名/作者 |
| search_library | 寻找已导入的参考论文 | 只读已授权文献库 |
| fetch_reference | 必要时读取可合法访问的外部参考论文 | 默认先本地；需联网工具、授权和服务端请求校验；不能绕过付费墙或宣称必定获得全文 |
| lookup_term | 查询上下文匹配的术语记忆 | 记录词义/领域/来源；不逐词拼接翻译 |
| propose_library_move | 按用户命名的目录提出整理方案 | 提案与实际移动分开；实际文件移动需要独立工具权限与可撤销记录 |

新增网络工具时服务端限制协议、目标域/地址、跳转和响应大小，不接受模型提供的任意内网目标。浏览器存储可以保存当前设备的文献与个性化版本，但不能冒充跨设备同步或系统文件权限。

## 两份 Skill 如何协作

阅读 Skill 负责完成当前任务；进化 Skill 不参与每次正文生成，而是在收到有效反馈后处理候选改进。

```text
用户反馈 + 对应任务证据
  → 分类（个人偏好 / 阅读策略 / 工程故障 / 不明确）
  → 最小候选改动 + 来源记录
  → 隔离环境对比：当前版本 vs 候选版本
  → 固定回归集 + 独立保留集 + 成本/延迟约束
  → 失败则拒绝；通过且符合权限则小范围启用
  → 观察实际表现；退化时恢复上一版本
```

“自进化”限定为反馈驱动的 Skill/策略优化，不是在线训练模型权重，也不保证每次尝试都会变好。两份 Skill 是两个职责，不必启动两个常驻模型进程。

## 防止无序进化

### 不可变边界与可变内容分离

将来源真实性、工具权限、评测门槛、成本上限、发布权限和进化器本身放在运行器的受保护策略中。进化模型只返回结构化候选改动；它没有写入源码、活跃 Skill 指针、评测答案或权限策略的工具。

允许自动调整的个人配置可以是翻译分段方式、解释详略等明确限定字段。阅读策略文本只在指定插槽中产生新版本。语义越权不能只靠 JSON Schema 发现，因此策略候选初期仍需独立评审；字段白名单和模型自检都不是充分的安全保证。

### 个人记忆不污染公共 Skill

本对话的反馈初始化项目主人的个人偏好，不默认成为所有网站用户的规则。一般策略应来自可验证失败模式，并通过跨任务评测后单独发布。论文正文不是反馈来源；旧要求和新要求只在同一适用范围内比较先后。

明确长期偏好不需要为了“学习”额外调用模型；可以通过确定性配置更新生效。模糊评价不直接持久化，避免把单次不满意当成永久规则。

### 有界自动化

建议首版默认采用“自动整理反馈、生成候选；策略启用需审核”。用户可在设置中启用允许范围内的自动试用，随时关闭。建议初始上限：每批一个候选、最多一次修订、同一问题失败后暂停；具体每日 token/费用上限由设置明确给出，缺失时不启动付费后台评测。

这些是建议默认值而非现有设置。不能因失败无限重试，不能绕过预算继续寻求好分数。事件队列需按用户/反馈去重；预算预留和候选晋升必须原子处理，避免多窗口重复扣费或并发覆盖版本。

浏览器关闭后不会承诺继续运行；若需要真正离线后台迭代，要再接独立的持久队列和调度执行服务。当前设计没有创建 Codex 定时任务。

### 用评测约束，而非“自己说进步了”

固定测试由工程侧维护，进化器只看到开发用反馈集；保留集及标准答案不暴露给候选生成过程。分别检测来源可验证性、主张支持关系、信息完整性、符号/数字保真、偏好遵循、取消与缓存隔离。

评测使用相同模型和参数、固定文献、版本隔离的缓存，并保留每次输出、工具调用、费用与延迟。不能只用同一个模型给自己评分；采用确定性检查、独立判断与人工抽检组合，证据弱时保持旧版本。出现伪造证据、越权或关键功能退化直接拒绝，不用综合分数抵消。

已列出 14 类回归种子，见进化 Skill 的反馈基线；它们目前是待实现的用例，不是已通过的测试。正式基准还需准备真实文献、人工核验的答案与独立保留样本。

### 版本、缓存和回滚

候选记录 parentVersion、反馈 ID、差异、评测报告、状态与批准依据。使用候选/试用/生效/回滚等显式状态，只有控制器能修改活跃版本指针。父版本发生变化则拒绝过期晋升，并重新对比测试。

将 skillVersion、profileVersion 及相关模型设置纳入回答缓存键，避免更新后仍展示旧格式的缓存。回滚恢复版本指针及对应命名空间，不批量删除全部历史或用户文件。运行中的任务继续使用已固定的版本，不能半途混用新旧指令。

## 按本对话落地的几个例子

- “翻译不要分段”：修改个人翻译格式；解释和总结不受影响。
- “术语希望打开思考”：保存术语任务设置；不覆盖翻译设置，不硬编码统一开关。
- “参考论文很重要”：增加条件性的参考来源追踪策略；没有原文时保留证据缺口。
- “左右分栏仍识别错误”：进入 PDF 引擎缺陷和回归用例，不进入 Skill 文本进化。
- “Invalid max_tokens”：进入 API 参数校验，不通过无限增大 Token 配额解决。

## 实施顺序与简历证据

1. 把现有提示词抽为真正可加载的阅读 Skill，补用户偏好隔离、版本固定和缓存兼容；不改变现有界面风格。
2. 为复杂问答接工具执行循环和来源核验，先用本地参考全文做闭环，再加授权网络来源。保留普通翻译快速路径。
3. 实现反馈日志、候选生成、固定回归和只读评测报告；先证明候选能被拒绝、预算能拦截、版本能回滚。
4. 在上述机制验证后，开放限定字段自动启用、策略候选小范围试用和退化回滚。
5. 实测固定流程、工具 Agent、受控进化三种版本，报告来源支持率、任务完成率、首字/总延迟、调用次数、Token/费用、误晋升率和回滚结果。没有实测就不填提升百分比。

建议项目名称：**Paper Agent：面向文献阅读的证据追踪与反馈驱动 Skill 优化系统**。

完整落地后可描述为：“设计并实现文献优先的工具调用 Agent，支持参考论文证据追踪；构建基于用户反馈的双 Skill 迭代机制，通过版本隔离、回归评测、预算约束与回滚控制策略更新。”

上述是未来完成后的表述。本轮只能如实表述为“完成双 Skill 与受控进化机制设计并编写规范草案”，不能写成已经实现自主联网、模型训练或自动进化闭环。
