# Paper Agent：LangGraph 文献阅读 Agent

## 可写入简历的版本

**技术栈：** React、TypeScript、LangGraph.js、LangChain、Zod、PDF.js、Zustand、IndexedDB。

**项目描述：** 面向论文阅读的工具调用 Agent，以文献助手为统一对话入口，支持当前文献检索、参考论文原文追踪、多文献问答和可追溯回答；保留划选翻译的低开销流式通道。

可如实使用的工作描述：

- 使用 LangGraph StateGraph 构建规划、工具执行、回答与来源定位检查流程，结合 LangChain Tool Calling 和 Zod 参数约束实现有界自主检索。
- 封装 11 类文献工具（6 类本地/参考工具、2 类外部工具、3 类 Wiki 工具），为证据绑定文档身份、PDF 页序号或在线段落、来源链接；核对参考论文 DOI/题名，区分全文、摘要和题录。
- 实现双 Skill 驱动的阅读策略与反馈工作流，对可变策略采用枚举白名单、父版本校验、人工审核和回滚；明确表达偏好可按用户设置自动采用。
- 将翻译快速路径与复杂问答分离，为解释缓存加入策略版本隔离，记录模型/工具调用次数、首字时间、总耗时及执行轨迹。
- 编写 46 项自动化机制测试，覆盖工具循环、模型接口协议、缺失原文、来源伪造、取消、重复调用、预算停止、策略越权、回滚，以及外部身份核对、响应大小限制和跳转限制、Wiki 草稿隔离、竞争更新和来源重新核对。

不要将其表述为“模型自训练”“完全自主进化”“已达到某准确率”“已降低费用某百分比”。目前没有对应测量证据。“受控反馈适配”比“无限自进化”更准确。

## 架构与实际调用

```text
React 文献助手
  └─ usePaperAssistant（取消、超时、策略快照）
      └─ LangGraph 阅读图
          ├─ plan：LangChain bindTools，模型选择下一步
          ├─ tools：Zod 校验，执行本地文献工具或调用 /api/papers 获取外部文献
          ├─ 条件边：再规划或进入回答
          ├─ answer：现有 OpenAI Compatible 流式适配器
          └─ verify：引用 ID/来源位置校验，生成运行记录

用户显式提交阅读反馈
  └─ LangGraph 反馈图
      ├─ 精确偏好/工程故障本地分类；其余最多一次模型请求
      ├─ guard：不可变枚举槽位检查
      └─ 候选 → 用户采用（仅精确表达偏好可选自动采用）→ 版本/回滚
```

两份 Skill 是加载进对应流程的指令资源，不是两个常驻进程。它们不改变模型权重。反馈图只调整 answerStyle、referenceDepth、termDetail；没有写入源码或自身指令的工具。

## 验收演示

1. 配置支持 OpenAI Compatible **Tool Calling** 的模型，导入有文字层的论文。点击宠物打开文献助手。
2. 问“这篇论文的方法是什么？请给来源”。展开“执行记录”，应看到实际检索/读页活动及来源片段，而非固定进度模板。
3. 问“请核对参考文献 1 的原始方法”。优先读取本地匹配原文；缺失时自动检索外部候选。核对 DOI 或题名/年份后读取；无法唯一确认身份时说明缺口。
4. 问对比两个已导入文献的具体问题，检查是否先检索目录，再读不同 documentId 的证据。点击来源打开正确文档页面。
5. 在“阅读策略与反馈”提交“以后回答简短一点”，检查候选差异。启用自动偏好时可直接生效；“希望更重视参考原文”只生成待审核策略。
6. 点击“恢复上一策略”，确认恢复行为、版本继续递增，旧候选不能覆盖新版本。
7. 提交“HTTP 400”或“左右分栏错误”：应归为工程故障，不更改阅读策略。
8. 发起任务后停止或切换文献，检查旧回答不再更新新文档。

以上是人工验收步骤，不表示已经用用户实际模型和论文完成了全部演示。

## 明确限制

- 浏览器本地部署方案：文献与策略保存在当前设备；同一浏览器配置文件中的使用者共享该状态，没有账号级隔离。
- 外部检索使用 Crossref、Europe PMC；全文支持 Europe PMC 开放 XML 和按编号读取 arXiv PDF（最多 12 MB、前 150 页）。其他论文可能只有摘要或题录，不绕过网站权限，不支持任意 URL 抓取。在线段落编号不是印刷页码。
- 引用核验检查真实证据 ID 与来源位置，不能证明每项自然语言主张正确。用户可展开原文核对。
- 检索仍为关键词/词频方法，不能在简历中写成已经使用向量数据库或语义 Embedding。
- 反馈候选没有独立答案质量评分；人工采用不是“评测自动通过”。代码禁止模型自行调整预算、权限或评测规则。
- 费用指标没有实际 Token 使用统计；“模型请求次数”不等于货币费用。最多 4 次规划请求加 1 次正文请求，正文无自动重试；反馈最多一次请求。
- 未完成跨设备同步、后台调度、持久化图 checkpoint、自动系统文件移动。后续可按真实需求独立实现。

框架依据：[LangGraph 官方快速开始](https://docs.langchain.com/oss/javascript/langgraph/quickstart)、[LangChain ChatOpenAI](https://docs.langchain.com/oss/javascript/integrations/chat/openai)。

## 外部文献读取（2026-09-07）

- `search_external_papers` 按题名、英文关键词或 DOI 查候选；arXiv 按编号/链接定位，不宣称覆盖所有网站。
- `read_reference` 本地缺失时自动追踪外部来源；身份无法唯一核对时保留候选，不将候选冒充被引用的原论文。
- `read_external_paper` 提取真实原文并继续使用词法检索；返回的 `sourceKind` 和 `locator` 会进入最终回答与引用面板。摘要来源标为摘要，题录不产生原文证据。
- 服务端仅访问固定学术域名，校验每次跳转，限制响应大小与超时；客户端全文缓存最多 8 篇、30 分钟，失败/题录不缓存。该缓存不跨设备持久化。
- 整次问答仍受 4 轮规划、8 次工具和 150 秒限制；外部搜索会向学术服务发送必要关键词或题录标识。
- 已验证的是外部 HTTP 与提取链路、模拟模型下的工具机制；未消耗用户模型 Key 进行真实模型问答验收。

接口依据：[Europe PMC 官方文档](https://europepmc.org/RestfulWebService)、[arXiv 官方 API 文档](https://github.com/arXiv/arxiv-docs/blob/develop/source/help/api/user-manual.md)。

## LLM Wiki（2026-09-08）

文献助手新增知识库：用户可将当前或多篇论文整理为知识页草稿，审核采用后用于后续检索。支持单篇、概念与专题比较、来源标签、双向关联、版本恢复与 Markdown 导出。新材料可更新已有页面，旧来源必须重新核对。当前采用浏览器 IndexedDB，不是云端同步，也不自动改写用户 PDF；普通聊天不自动写入。完整设计、使用步骤与验证范围见 [LLM Wiki 说明](llm-wiki.md)。
